# ADR 0002: MySQL for central records

Status: Accepted

## Context

Consolidated records and reporting need a shared database the farm can host and query.

## Decision

Use MySQL with Drizzle and mysql2 on the central server. The unique key on session_id enforces one transaction per session.

## Consequences

Familiar, widely hosted. Local development needs a MySQL instance, which departs from the preference for no installed services; this is accepted and documented in the README.

Schema changes are SQL migrations generated by drizzle-kit and applied with Drizzle's migrator. The `transactions` table is append-only: triggers reject UPDATE and DELETE.

For tests, the MySQL suite is opt-in. Set `MYSQL_TEST_URL` to a database whose name ends in `_test` (the suite drops its tables). Without it the suite is skipped and the in-memory repository, which shares the same contract tests, still runs. A throwaway container is the simplest local instance:

    docker run -d --name agriflow-mysql -e MYSQL_ROOT_PASSWORD=<password> -e MYSQL_DATABASE=agriflow_test -p 127.0.0.1:3307:3306 mysql:8.4

Docker is used only for this disposable test database. The application does not depend on it.
